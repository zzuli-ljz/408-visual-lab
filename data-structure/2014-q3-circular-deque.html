题面

循环队列放在一维数组 A[0…M−1] 中，end1 指向队头元素，end2 指向队尾元素的后一个位置。假设队列两端均可进行入队和出队操作，队列中最多能容纳 M−1 个元素。初始时为空。下列判断队空和队满的条件中，正确的是（　）。

A. 队空: end1 == end2；队满: end1 == (end2+1) mod M ✓ 正确（下面会用动画证明）
B. 队空: end1 == end2；队满: end1 == (end2+1) mod (M−1) ✗ 下标应对 M 取模
C. 队空: end2 == (end1+1) mod M；队满: end1 == (end2+1) mod M ✗ 判空条件其实是「个数 = 1」
D. 队空: end1 == (end2+1) mod M；队满: end1 == (end2+1) mod (M−1) ✗ 空和满写反了

    选项速览

    A. 队空: end1 == end2；队满: end1 == (end2+1) mod M ✓ 个数 = 0 判空，个数 = M−1 判满，与方向无关
    B. 队空: end1 == end2；队满: end1 == (end2+1) mod (M−1) ✗ 数组下标循环必须 mod M，mod (M−1) 会越界
    C. 队空: end2 == (end1+1) mod M；队满: end1 == (end2+1) mod M ✗ 该「判空」式实际表示个数 = 1，不是空
    D. 队空: end1 == (end2+1) mod M；队满: end1 == (end2+1) mod (M−1) ✗ 它的「判空」恰恰是个数 = M−1 的队满状态

    文字解析：为什么选 A

    1. 先抓住「不变量」：元素个数

    无论是队头入队、队头出队，还是队尾入队、队尾出队，变化的只是 end1 或 end2 各自移动一格，元素个数永远等于 (end2 − end1 + M) mod M。这是解开本题的钥匙——「两端都能操作」并不会让个数公式失效：

    操作end1end2元素个数
    队尾入队不变+1（mod M）+1
    队尾出队不变−1（mod M）−1
    队头入队−1（mod M）不变+1
    队头出队+1（mod M）不变−1

    2. 再把个数翻译成指针条件

    · 队空：个数 = 0 ⟺ (end2 − end1) mod M = 0 ⟺ 两个指针重合 ⟺ end1 == end2。
    · 队满：个数 = M − 1 ⟺ (end2 − end1) mod M = M − 1 ⟺ end1 在环上比 end2「多走一格」⟺ end1 == (end2+1) mod M。

    这正是 选项 A 。官方解析用的是特例法：假设 M−1 个元素存放在 A[0]～A[M−2]，队头 A[0]、队尾 A[M−2]，则 end1 = 0、end2 = M−1，代入即得 end1 == (end2+1) mod M。

    3. 为什么必须空出一个格子（容量只有 M−1）

    若把第 M 个元素也放进去，end2 绕回后正好与 end1 重合，状态 (end1 = end2) 和「队空」长得一模一样，程序就无法区分空和满了。所以循环队列约定：牺牲一个存储单元，用 (end2+1) mod M 是否等于 end1 来判满。看动画第 6 步（入队被拒绝）就是这个道理。

    4. 两个易错点

    ① 别被「两端均可入队」吓到——它只决定 end1 / end2 谁在动，不改变个数公式，所以判满条件只有一个，不会出现「两个满条件」。动画第 8 步和第 15 步分别从两头填满，条件完全一样。
    ② 注意 end2 的定义是「队尾元素的后一个位置」；有些教材约定 end2 直接指向队尾元素，那时的条件会不同，别背串了。
